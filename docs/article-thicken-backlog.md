## Seria基準（合格ライン）

`/2026-08-29/seria/` が満たしている読者向け深さ。各商品ブロックとページ全体で次を揃える。

| 必須 | 中身 |
| --- | --- |
| 用途 | 何に使う商品か、どんな人・場面に向くか（商品ごとに1段落以上） |
| 選び方 | 似た商品との違い、容量・入数・タイプの見分け方 |
| 注意 | 使い方・取り違え・通販単位・表示確認。効果は断定しない |
| FAQ | 見出し「よくある質問」＋本文3問以上＋`FAQPage` JSON-LD |
| 目的別 | 「目的別に選ぶならどれ？」相当。読者が自分の用途で辿れる |
| 購入意図 | 既存CTAを残す。無い場合は公式の探し方。新規のcommerce型は足さない |
| 読者文 | 在庫数・JAN照合時刻・「完全一致」など運用メモは出さない |
| H1/title | 番組＋日付＋テーマが読める。放送前のまま残さない（確定後） |

本文は読者があとから商品を選ぶための結果だけ。内部手順・照合ログは書かない。

## 各PRの必須添付

1. **Media/content checklist**（下の共通表）
2. **before/after** URLごと（欠け → 足したブロック）
3. **acceptance_checks** WEB Designerが画面で確認できる項目

### Media / content checklist（共通）

- [ ] 同じURL。新規パスを増やしていない
- [ ] 番組公式（またはメーカー公式）で確認できた名前・価格・順位だけ
- [ ] 独自ランキング・独自1位を足していない
- [ ] 商品ごとに用途・選び方・注意がある
- [ ] 「よくある質問」が見える。3問以上。JSON-LDと本文が一致
- [ ] 目的別の選び方がある
- [ ] 既存の楽天/公式CTA本数を減らしていない。新規commerce型を足していない
- [ ] 読者文だけ。在庫数・照合時刻・JANメモを本文に出していない
- [ ] H1とtitleが番組＋日付＋テーマを示す
- [ ] 出典リンクが残っている
- [ ] 広告注記が残っている
- [ ] レイアウトは既存CSS。新規フレームワークなし

### WEB Designer 受け入れ（画面）

1. 対象URLを開く。H1が読める
2. 各商品カードで、用途・選び方・注意が目に入る
3. ページ下部にFAQがある
4. CTAを押さずに、リンク先ドメインと `rel` が以前と同じ本数であることを確認
5. スマホ幅でカードが崩れない
6. 関連記事・出典が残っている
